2. GTM: setările containerului și Consent Mode v2

2.1 Cum funcționează împreună cu pluginul de cookies (EF Cookie Consent)

Site-ul face deja partea de Consent Mode v2 – în GTM nu se adaugă niciun șablon de consimțământ (CMP). Ordinea pe fiecare pagină:

  1. În <head>, înaintea oricărui alt script, pluginul trimite gtag('consent', 'default', …) cu tot pe denied (în afară de security_storage), plus wait_for_update: 500 și ads_data_redaction: true.
  2. Dacă vizitatorul a ales deja (cookie efcc_consent, ținut 180 de zile), trimite imediat gtag('consent', 'update', …) cu alegerea lui și evenimentul efcc_consent_ready.
  3. Abia apoi GTM4WP încarcă containerul GTM-NFMC9Z3.
  4. Când vizitatorul apasă Accept all / Reject all / Save my choices (sau își schimbă alegerea din butonul cu cookie), pluginul trimite consent update și evenimentul efcc_consent_update; pentru fiecare categorie acceptată și efcc_statistics_granted, efcc_marketing_granted, efcc_preferences_granted.
  5. Vizitatorii cu Global Privacy Control activ în browser sunt tratați ca „Reject all”.

Modul este Advanced: GTM se încarcă mereu, iar tag-urile Google trimit, până la acord, doar „pings” fără cookie-uri (GA4 și Google Ads pot modela conversiile). Setările se schimbă din WordPress → Cookie Consent → Google Consent Mode (acolo e și opțiunea Basic, în care GTM se încarcă doar după acord). În tab-ul Google Consent Mode, Load GTM trebuie să rămână pe „By another plugin” (GTM4WP încarcă containerul), iar în GTM4WP, setările proprii de Consent Mode rămân oprite – altfel ar exista două surse de „default”.

2.2 Setările containerului

  1. Admin → Container Settings → bifează Enable consent overview → Save. Apare iconița de scut în lista de tag-uri.
  2. Tags: pune pe pauză / șterge orice șablon de cookie banner sau CMP vechi (Cookiebot, CookieYes, „Consent Mode (Google tags)” de la Simo Ahava etc.) și orice tag care trimite consent default. Rămâne o singură sursă: site-ul.
  3. Verifică tag-urile site-ului vechi (Universal Analytics, conversii vechi): pune pe pauză ce nu mai funcționează.
  4. Variables → Configure (Built-In Variables): bifează Page Hostname, Page Path, Event, Click URL, Form ID.

2.4 Ca tag-urile non-Google să pornească imediat după „Accept”

Un tag cu additional consent care rulează pe All Pages e blocat la încărcarea paginii, dacă vizitatorul nu a acceptat încă – și nu mai pornește pe pagina respectivă după ce acceptă. De aceea:

  1. Trigger nou → Custom Event → Event name efcc_consent_update → nume CE - consent update.
  2. Adaugă-l la tag-urile non-Google pe lângă triggerul lor obișnuit (ex. Meta Pixel: All Pages + CE - consent update).
  3. Ca să nu ruleze de două ori pe aceeași pagină, în Advanced Settings → Tag firing options alege Once per page.
  4. Alternativ, pe categorii: triggere Custom Event efcc_marketing_granted (pentru marketing) și efcc_statistics_granted (pentru statistici) – pornesc doar dacă vizitatorul a acceptat acea categorie.

2.6 Servicii noi

Orice serviciu nou adăugat în GTM (ex. Meta Pixel) trebuie adăugat și în WordPress → Cookie Consent → Services (există presetări): apare cu comutatorul lui în fereastra de preferințe și cu cookie-urile lui în Cookie Policy. După adăugare: Cookies & scan → Scan the website, iar dacă e un serviciu nou de marketing, Tools → Ask everyone again, ca vizitatorii să fie întrebați din nou.

2.7 Verificare

  1. GTM → Preview → site-ul, într-o fereastră fără cookie-uri anterioare (incognito).
  2. În Tag Assistant, tab-ul Consent, la primul eveniment (Consent Initialization / primul Message): On-page Default = Denied pentru ad_storage, analytics_storage, ad_user_data, ad_personalization.
  3. Apasă Reject all: evenimentul efcc_consent_update apare, On-page Update rămâne Denied; tag-urile non-Google apar la Tags Blocked by Consent.
  4. Apasă butonul cu cookie (stânga-jos) → Accept all: On-page Update = Granted; apar efcc_marketing_granted / efcc_statistics_granted, iar tag-urile non-Google pornesc.
  5. Reîncarcă pagina: încă de la primul eveniment, On-page Update = Granted (alegerea e reținută).
  6. În GA4 → Admin → Data collection / Google Ads → Consent, după 1–2 zile apare „Consent mode active”.

6. GA4: setări și dimensiuni personalizate

6.1 Setări

  1. Admin → Data streams → (site) → Enhanced measurement → ⚙: oprește „Form interactions” (site-ul trimite deja form_start / form_submit / generate_lead; altfel se dublează). Restul poate rămâne pornit.
  2. Admin → Data settings → Data retention: 14 months (altfel explorările nu pot compara anul trecut).
  3. Admin → Key events: purchase e automat; marchează și generate_lead.
  4. Admin → Data streams → Configure tag settings → List unwanted referrals: adaugă domeniul plății Lloyds (lloydsbankcardnet.co.uk / domeniul paginii de plată) și eco-fridge.o2dev.de, ca revenirea de la plată să nu pară o vizită nouă.
  5. Admin → Product links: leagă Google Ads și Merchant Center (ID 133011514).
  6. Admin → Data filters (opțional): Internal traffic cu IP-ul biroului.

7. Google Ads și Merchant Center

  • Google Ads → Goals → Conversions → Settings → Enhanced conversions: pornește-le, metoda Google Tag Manager.
  • Google Ads → Settings → Consent: confirmă că folosiți Consent Mode (EF Cookie Consent trimite ad_user_data și ad_personalization).
  • Merchant Center 133011514 (după lansare): feed https://eco-fridge.co.uk/feed/google-merchant/; ID-urile produselor din feed sunt identice cu item_id din dataLayer, deci remarketingul și raportările pe produs se potrivesc.

8. Testare (înainte de Publish)

  1. Pune temporar condiția de hostname din triggere pe eco-fridge\.(co\.uk|o2dev\.de).
  2. GTM → Preview → URL https://eco-fridge.o2dev.de/ (staging cere parola în fereastra deschisă de Tag Assistant).
  3. În Tag Assistant, tab-ul Consent: la încărcare Default = denied; după „Accept all” în banner → Update = granted.
  4. Parcurge: categorie → produs (view_item) → bifează Removal / Warranty → Add to basket (add_to_cart) → coș → checkout.
  5. Comandă de test cu Direct bank transfer (fără plată reală) → pe „Order received” verifică evenimentul purchase: Data Layer trebuie să aibă ecommerce, order_details, user_data, iar tag-urile 5.3 și Ads Purchase să fie Fired.
  6. Formularul de contact (cu mesaj „TEST – please ignore”): generate_lead + tag-urile lead Fired.
  7. GA4 → Admin → DebugView: evenimentele apar cu parametrii lor.
  8. Spune-i lui Claude numerele comenzilor de test, ca să le șteargă (lansarea se face din staging).
  9. Pune la loc condiția de hostname equals eco-fridge.co.uk.

10. Publicare și ziua lansării

  1. Containerul e folosit și de site-ul vechi: tag-urile noi se bazează pe evenimente pe care doar site-ul nou le trimite, deci pot fi publicate înainte de lansare fără să strice site-ul vechi.
  2. Submit → Version name „New site – GA4 ecommerce + consent” → Publish.
  3. În ziua lansării: verifică în GA4 → Realtime că apar vizite și view_item de pe eco-fridge.co.uk.
  4. După prima comandă reală: în GA4 → Reports → Monetisation → Ecommerce purchases, apoi în Google Ads → Conversions (status „Recording conversions”).
  5. După 7 zile: Google Ads → Enhanced conversions → Diagnostics (trebuie „Excellent” / „Good”).
Ce face deja site-ul (nu trebuie setat în GTM): Consent Mode v2 default + update, GTM încărcat de GTM4WP după consimțământ, datele de ecommerce cu ID-urile din feed, detaliile comenzii, locația, sursa de trafic, user_data criptat, evenimentele din formular.
